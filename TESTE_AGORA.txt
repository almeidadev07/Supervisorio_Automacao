## TESTE AGORA

1. Reinicie o sistema:
   
   .\start.ps1

2. VEJA OS LOGS ao iniciar. Procure por:
   
   [PlcPolling] ✅ Manager configurado com tradução de X tags
   
   Se X = 0 → Problema! Comm_map não carregou
   Se X > 0 → OK! Tem X tags disponíveis

3. Tente escrever velocidade na interface

4. VEJA OS LOGS. Vai aparecer UMA destas opções:

   OPÇÃO A - TAG NÃO EXISTE (erro):
   ═════════════════════════════════════════════════════
   [PlcPolling] ⚠️ Tag "..." não encontrada no comm_map
   [PlcManager] ❌ Tag "..." não pode ser traduzida
   ═════════════════════════════════════════════════════
   
   SOLUÇÃO: A tag não está no comm_map!
            Veja abaixo como descobrir o nome correto.
   
   
   OPÇÃO B - SUCESSO (tudo certo):
   ═════════════════════════════════════════════════════
   [PlcManager] 📝 Tentando escrever 1 tags: [...]
   [PlcManager] 📍 Tag "..." → "DB1,REAL48"
   [PlcManager] ✅ Escrita bem-sucedida!
   ═════════════════════════════════════════════════════
   
   ÓTIMO! Funcionou! Verifique se valor mudou no PLC.

## SE DER ERRO "TAG NÃO ENCONTRADA"

Isso significa que o nome da tag no código não corresponde ao comm_map.

1. Descubra qual comm_map está sendo usado:
   
   curl http://127.0.0.1:8081/api/stats
   
   Procure por: "COMM_MAP_PATH": "config/comm_map/700CX.json"

2. Veja as tags de velocidade disponíveis:
   
   Get-Content config\comm_map\700CX.json | Select-String "veloc"

3. Me envie o resultado!

## SOBRE O ATRASO DE 10 SEGUNDOS

O atraso pode ser por 2 motivos:

1. Polling HTTP do frontend está em 5 segundos
   → Solução: Reduzir para 1 segundo (veja CORRECAO_ESCRITA_ATRASO.md)

2. Socket.IO não está funcionando
   → Abra F12 no navegador e veja se aparece:
     [GRID] ✅ Socket.IO conectado
